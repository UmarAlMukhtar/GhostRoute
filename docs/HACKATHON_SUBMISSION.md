# GhostRoute — submission narrative

**Tagline:** Navigate to safety when ordinary routes become unsafe.

**Team:** Umar Al Mukhtar, Sanjay KP and Alphons N J. GitHub handles and individual contributions await confirmation. This is a prepared narrative, not a claim that submission has occurred.

## Problem

A short route is useful only while its roads remain available. During a disruption, blocked roads can change access to a destination or remove access altogether. Mapping services may already support closures; GhostRoute does not claim otherwise. The project makes the graph consequences of illustrative flooding visible and reproducible in a manageable Ernakulam region.

## Proposed solution

An interactive map displays actual OpenStreetMap road geometry. Users choose endpoints or enter Demo Mode, calculate a distance-weighted route, then activate deterministic flood polygons. Geographic intersections identify affected physical segments; both directions become unavailable. Dijkstra recalculates the shortest remaining route, or reports that none exists. Original and updated paths, blocked roads and distance comparisons appear together.

## Innovation and differentiation

The demonstrable contribution is a transparent, self-contained explanation of disaster-related road availability: real graph topology, explicit closure rules, deterministic replay and inspectable calculations. Routes are not generated by a language model or replaced with hand-drawn alternative lines. Codex assisted software development; the running routing and simulation engines use conventional graph and spatial algorithms. No unsupported claim of uniqueness, prediction or live hazard detection is made.

## Technical implementation

Next.js, strict TypeScript and React provide the dashboard; MapLibre renders geographic sources/layers. The local OSM-derived dataset has 1,719 nodes, 3,712 directed edges and 1,856 physical segments. A binary-heap Dijkstra engine uses edge distances and closure sets without mutating the graph. Focused Turf modules validate/intersect polygons and road geometry. Browser state derives baseline/current routes from endpoints and deterministic scenario stages. Vitest and Playwright test real data as well as synthetic correctness fixtures. No backend, paid API, authentication or runtime Overpass dependency is required.

## Demonstration walkthrough

Choose **Demo Mode** and advance through the cues: regional overview → Hospital Road baseline → localized flood/detour → three expanding stages → unavailable destination → restored baseline. **Reset demo** restarts in one click; manual controls remain available and exit the guide when used. All displayed metrics are calculated at runtime.

Verified fixture outcomes: baseline 944.333 m; Hospital flood closes 5 segments and yields 1,411.110 m; the final expanding stage closes 27 and yields 1,731.155 m. Destination flooding closes 21 and produces an explicit unavailable result. These are reproducible simulated conditions, not observations.

## Real-world impact and limitations

The current value is an educational and technical prototype for judges, contributors and people exploring how closures affect networks. Operational evacuation use would require authoritative current hazards, reviewed access rules, verified destinations, validation with emergency services and clear responsibility.

Simulation only. Flood zones are illustrative and do not represent verified live conditions. Routes are not certified safe for emergency use. The small frozen OSM extract may be incomplete or stale. The 2D intersection model ignores elevation/depth and can overblock bridges. Demo endpoints are not official shelters. WebGL is required for map graphics; bundled roads remain useful when optional basemap tiles fail. No hosted deployment or agency integration is claimed.

## Future scope

Validate access and geography with domain experts; add provenance and freshness for verified closures; collaborate on verified destination data; evaluate accessibility attributes and offline distribution. Predictive hazards and multi-user reporting are separate future work, not hackathon claims.
